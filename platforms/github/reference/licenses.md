# License Selection Guide

> Choose a software license that matches how you want others to use your work.

## What a license is

A license is a legal permission document. Without one, others usually do not
have clear rights to use, modify, or redistribute your code.

> [!IMPORTANT]
> This page is educational, not legal advice.

## Common licenses at a glance

| License | Use case | Keep source open? | Notes |
|---------|----------|-------------------|-------|
| MIT | Maximum reuse, low friction | No | Simple, permissive, very common |
| Apache-2.0 | Permissive with patent grant | No | Good default for many teams |
| GPL-3.0 | Strong copyleft | Yes (for derivatives) | Forces derivatives to stay GPL |
| BSD-3-Clause | Permissive | No | Similar spirit to MIT |
| MPL-2.0 | File-level copyleft | Partly | Copyleft applies per-file |

## Beginner-friendly decision path

- Want easiest adoption and broad reuse: MIT or Apache-2.0.
- Want derivative works to stay open: GPL-3.0.
- Need explicit patent language: Apache-2.0.

## How to apply a license in GitHub

1. Add a `LICENSE` file at repository root.
2. Use standard license text from an official template.
3. Mention the license in your `README.md`.

> [!WARNING]
> Copying random license text from unknown sources can create legal ambiguity.
> Use vetted templates (for example from choosealicense.com).
