# Issues, PRs, and Discussions

> Use the right GitHub channel for the right kind of work.

## At a glance

| Tool | Best for | Output |
|------|----------|--------|
| Issues | Track work, bugs, requests | Actionable tasks |
| Pull Requests | Propose and review code changes | Reviewed merges |
| Discussions | Open-ended questions and community threads | Shared knowledge |

## Issue best practices

- Use templates for bug reports and feature requests.
- Include reproduction steps and expected behavior.
- Link related pull requests.

## Pull request best practices

- Keep PR scope focused.
- Explain what changed and why.
- Include validation steps (`tests`, screenshots, logs).

## Discussion best practices

- Use discussions for Q&A and design exploration.
- Convert solved discussions into docs where useful.

> [!TIP]
> When users ask the same question repeatedly, create docs and link them in discussions.

> [!WARNING]
> Do not use discussions as a substitute for bug tracking. Bugs belong in issues.
