# Repository Naming and Scope

> A repository name should tell people what the project is before they open it.

**You will learn:**
- How to name repositories clearly
- How to define project scope in one sentence
- How naming affects discoverability and maintenance

**Before this page, you should know:** [Create Your First Repository](../01-introduction-and-setup/03-create-your-first-repository.md)

---

## Naming rules that work

- Use lowercase names.
- Use hyphens for multi-word names.
- Avoid vague names like `test`, `new-project`, `app`.

Good examples:
- `academy`
- `rust-cli-template`
- `github-masterclass-notes`

## Define scope immediately

Your scope line answers one question: "What problem does this repository solve?"

Example scope line:

```text
A beginner-first curriculum for learning GitHub workflows from setup to releases.
```

> [!IMPORTANT]
> Scope is not a feature list. Scope is the project boundary.

## Prevent scope creep

If a new idea does not match your scope sentence, create a new repository or
open a proposal issue before adding it.

---

## Recap

- Repository names should be short, specific, and searchable.
- Scope should be explicit in repository description and README.
- Clear scope prevents chaotic growth.

## Try it yourself

Rewrite your repository description so a first-time visitor understands your
project in one sentence.
