# Licenses for Beginners

> A license tells others what they are allowed to do with your code.

**You will learn:**
- Why every public repository needs a license
- How to pick a beginner-friendly license
- How to apply and communicate license choice

**Before this page, you should know:** [Project Structure and Documentation](./02-project-structure-and-documentation.md)

---

## No license means uncertainty

Without a license, users may be legally blocked from reusing your work.

## Fast selection path

- Want broad adoption: MIT or Apache-2.0.
- Want derivative works to stay open: GPL-3.0.

## Applying a license

1. Add `LICENSE` file to repository root.
2. Use standard text from trusted sources.
3. Mention license in `README.md`.

> [!NOTE]
> For deeper comparison, use [License Selection Guide](../../reference/licenses.md).

> [!WARNING]
> This course gives educational guidance, not legal advice.

---

## Recap

- License choice affects project reuse and contributor expectations.
- Public repositories should include a clear license.
- Communicate license in both `LICENSE` and `README.md`.

## Try it yourself

Add a `LICENSE` file to a practice repository and add a `License` section in
its README.
