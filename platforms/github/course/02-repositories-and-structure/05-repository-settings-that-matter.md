# Repository Settings That Matter

> A few settings prevent most early collaboration problems.

**You will learn:**
- Which repository settings to configure first
- Why branch protection matters
- How settings connect to quality and safety

**Before this page, you should know:** [Versioning and Changelog Management](./04-versioning-and-changelog-management.md)

---

## Minimum settings checklist

- Add description and topics.
- Set default branch.
- Protect default branch.
- Require pull requests for team merges.
- Enable security alerts.

## Branch protection basics

Branch protection can require:
- pull request review
- status checks
- linear history

> [!WARNING]
> Disabling protection on active repositories makes accidental breakage much easier.

## Templates and defaults

Use `.github/` templates for:
- issues
- pull requests
- discussions guidance

This standardizes communication and improves response quality.

---

## Recap

- Repository settings are operational guardrails.
- Branch protection is one of the highest-value safety settings.
- Templates reduce low-quality issue and PR submissions.

## Try it yourself

Enable branch protection on a test repo and require one approving review before
merge.
