# README and CONTRIBUTING Foundations

> Good docs are the front door for users and contributors.

**You will learn:**
- What README must include
- Why CONTRIBUTING.md reduces maintainer load
- How to create clear expectations for contributors

**Before this page, you should know:** [Merging and Conflict Handling](../03-collaboration-and-review/04-merging-and-conflict-handling.md)

---

## README minimum sections

- What this project is
- How to install
- How to use
- How to contribute
- License

## CONTRIBUTING.md minimum sections

- branch naming
- commit message format
- pull request checklist
- code style expectations

> [!IMPORTANT]
> If contribution rules are not written, contributors will guess.

---

## Recap

- README attracts and orients users.
- CONTRIBUTING.md standardizes collaboration.
- Clear docs reduce repeated support questions.

## Try it yourself

Add a PR checklist to `CONTRIBUTING.md` in a practice repository.
