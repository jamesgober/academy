# Discussions and Communication Channels

> Use the right channel for the right message.

**You will learn:**
- When to use Issues vs Discussions
- How to reduce noise in project communication
- How to turn repeated answers into docs

**Before this page, you should know:** [README and CONTRIBUTING Foundations](./01-readme-and-contributing-foundations.md)

---

## Channel split

- **Issues**: track actionable work.
- **Pull Requests**: review proposed changes.
- **Discussions**: open-ended Q&A and ideation.

## Maintain healthy communication

- Pin important discussions.
- Use labels/categories.
- Link final decisions to docs.

> [!TIP]
> A question answered 3+ times belongs in FAQ or docs.

---

## Recap

- Communication quality is part of project quality.
- Using the right channel prevents confusion.
- Documentation should absorb repeated answers.

## Try it yourself

Create a Discussion category for Q&A and one for Ideas in a test repository.
