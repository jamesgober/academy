# GitHub Capstone Project

> Build a complete repository workflow that demonstrates end-to-end GitHub fluency.

**You will practice:**
- repository setup and metadata
- branching, issues, PRs, and merge flow
- CI checks and branch protection
- semantic versioning, tags, release notes, and changelog discipline

**Before this page, you should know:**
- [Tags, Releases, and Release Notes](./05-tags-releases-and-release-notes.md)

---

## Capstone brief

Create a practice project repository and implement all of the following:

1. Repository setup
   - README, LICENSE, CHANGELOG, CONTRIBUTING
   - Description and topics filled in
2. Collaboration setup
   - Issue templates and PR template
   - Branch protection requiring CI status checks
3. Workflow setup
   - CI workflow file in `.github/workflows/ci.yml`
   - At least format, lint, and test checks
4. Delivery setup
   - Tag at least one release
   - Publish release notes from changelog entries

## Evaluation checklist

- Is repository purpose obvious in 20 seconds?
- Can a contributor open a clean PR without asking hidden rules?
- Does CI block broken changes from main?
- Are versions and release notes consistent and meaningful?
