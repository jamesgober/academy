# Issues and Pull Requests Workflow

> Issues define work. Pull requests propose and review changes.

**You will learn:**
- How issues and PRs connect
- What a good PR description includes
- How to review without creating friction

**Before this page, you should know:** [Working on Branches Day to Day](./02-working-on-branches-day-to-day.md)

---

## Workflow map

1. Create an issue for the task.
2. Create a branch linked to that issue.
3. Implement and commit changes.
4. Open pull request referencing the issue.
5. Review, update, and merge.

## PR template essentials

Include:
- what changed
- why it changed
- how to test/verify
- related issue link

## Review etiquette

- Critique code, not people.
- Ask clear questions.
- Suggest actionable improvements.

> [!IMPORTANT]
> A pull request is a conversation, not just a gate.

---

## Recap

- Issues and PRs create traceable project history.
- Good PR descriptions reduce back-and-forth.
- Respectful review improves both code and team culture.

## Try it yourself

Open a PR from a docs branch and include a 3-line validation checklist in the
PR description.
