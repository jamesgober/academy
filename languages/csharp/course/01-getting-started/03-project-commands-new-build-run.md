# Project Commands: `new`, `build`, `run`

C# development usually flows through the `dotnet` command-line tool.

The three commands you will use constantly are:

```text
dotnet new    create a project
dotnet build  compile and check the project
dotnet run    build if needed, then execute the app
```

## The Folder Model

Create a project:

```bash
dotnet new console -n app-demo
```

This creates:

```text
app-demo/
  Program.cs
  app-demo.csproj
  obj/
```

After building, you will also see `bin/`:

```text
app-demo/
  Program.cs
  app-demo.csproj
  bin/
  obj/
```

Beginner translation:

- `Program.cs` is the code you edit.
- `.csproj` is the project recipe.
- `obj/` is intermediate build data.
- `bin/` contains compiled output.

Usually, you edit `Program.cs` and `.csproj`. You do not hand-edit `bin/` or
`obj/`.

## `dotnet new`

`dotnet new` creates files from a template.

```bash
dotnet new console -n app-demo
```

Read it as:

```text
create a new console app named app-demo
```

Common templates:

```bash
dotnet new console -n my-app
dotnet new classlib -n my-library
dotnet new xunit -n my-tests
dotnet new sln -n my-solution
```

You can list installed templates:

```bash
dotnet new list
```

## `dotnet build`

Move into the project:

```bash
cd app-demo
```

Build:

```bash
dotnet build
```

`dotnet build` compiles the project and reports errors or warnings.

Use it when you want to ask:

```text
Does this project compile?
```

If build succeeds, you may see output ending with something like:

```text
Build succeeded.
    0 Warning(s)
    0 Error(s)
```

If build fails, read the first error first. Later errors can be side effects.

## `dotnet run`

Run the app:

```bash
dotnet run
```

`dotnet run` builds if needed, then starts the program.

Use it when you want to ask:

```text
What does this program do when it runs?
```

## Build Versus Run

Build checks whether the project can compile.

Run executes the app.

```text
Program.cs
  |
  | dotnet build
  v
compiled output
  |
  | dotnet run
  v
program behavior
```

Examples:

- Missing semicolon: build problem.
- Wrong printed message: run behavior.
- Misspelled `Console`: build problem.
- Logic that adds the wrong numbers: run behavior.

## Useful Companion Commands

Clean generated build output:

```bash
dotnet clean
```

Show SDK information:

```bash
dotnet --info
```

Show installed SDK versions:

```bash
dotnet --list-sdks
```

Format code if the formatter is available:

```bash
dotnet format
```

Run tests when you have a test project:

```bash
dotnet test
```

## A Good Beginner Workflow

Use this loop:

```text
1. Edit one small thing.
2. Save.
3. dotnet build.
4. Fix the first error or warning.
5. dotnet run.
6. Read the output.
```

When everything is easy, `dotnet run` is convenient. When errors get confusing,
use `dotnet build` first because it keeps your attention on compilation.

## Troubleshooting

### `Couldn't find a project to run`

You are probably not inside a folder containing a `.csproj` file.

Check:

```bash
pwd
ls
```

PowerShell:

```powershell
Get-Location
dir
```

Move into the project folder:

```bash
cd app-demo
```

### The App Still Prints Old Text

Make sure you saved `Program.cs`.

Also confirm you are running the project you edited. It is common to create two
practice folders and run the wrong one.

### Build Creates Lots Of Files

That is normal. The `bin/` and `obj/` folders are generated by the build system.
Do not panic when they appear.

## Practice

Create a project named `command-practice`:

```bash
dotnet new console -n command-practice
cd command-practice
dotnet build
dotnet run
```

Then edit `Program.cs`, build again, and run again.

Finally, run:

```bash
dotnet clean
dotnet build
dotnet run
```

You should now be able to explain what each command did.
