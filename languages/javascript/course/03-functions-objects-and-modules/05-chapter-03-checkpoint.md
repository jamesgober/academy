# Chapter 03 Checkpoint

> Validate your function and module design before async complexity is introduced.

## You should be able to do all of this

- choose function form intentionally
- explain and use closures safely
- model data with objects/classes
- split code into reusable ES modules

## Mini challenge

Build a tiny utility package with:
- one math module
- one string module
- one entry file importing both

---

## Recap

- Function boundaries shape code quality.
- Closures are useful when state lifetime is intentional.
- Modules are architectural building blocks, not optional style.

## Try it yourself

Refactor one larger file into three modules with clear responsibilities.
